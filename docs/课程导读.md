## day01 · 最早期的四个练习（命令行时代）

这几份代码写在还没用 Eclipse 的时候，所以文件放在 `src/day01/` 下，
它们是最早的「照着自己的理解敲一遍」的代码，朴素但真实。

| 文件 | 在练什么 | 运行后你会看到 |
| --- | --- | --- |
| `Check.java` | `if - else` 分支 | `今天真热，注意防暑` |
| `Loop.java` | `for` 循环的三要素 | `这是第10遍` 一路递减到 `这是第2遍`，共 5 行 |
| `Sum100.java` | `for` + **累加器** | `总和是5050` |
| `Sum200.java` | 累加练习（踩坑记录） | 50 行「总和为6 / 8 / 11 …」 |

**这一批里最值得记住的两点：**

**1. for 循环的三个部分，就是「循环三要素」**

```java
for (int i = 10; i >= 1; i = i - 2)
//   ①起始值   ②结束条件   ③每轮结束后怎么变
```

- `Loop.java` 里 `i = i - 2`：每次减 2，所以只会经过 10、8、6、4、2，一共 5 次；
- `Sum100.java` 里 `i = i + 1`：每次加 1，从 1 走到 100。

**2. `Sum200.java` 保留了一个真实的坑**

```java
for (int i = 1; i <= 50; i++) {
    a = a + i;
    System.out.println("总和为" + a);   // ← 打印写在了循环「里面」
}
```

`System.out.println` 写在循环里面，就会**每加一次就打印一行**，输出 50 行；
写在循环外面（也就是 `}` 之后），才会只打印最后一个结果。
这个「打印语句放错层级」的坑，是这个文件留给自己的提醒。

**动手改一改：** 把 `Sum200.java` 里的 `System.out.println` 挪到循环外面，看看输出从 50 行变成几行。

### 2.1 最容易吃亏的一课：整数除法 `Divide.java`

```java
System.out.println(10 / 3);   // 输出 3     ← 不是 3.3333！
System.out.println(10.0 / 3); // 输出 3.3333333333333335
```

**两个整数相除，Java 会直接丢掉小数部分。**
以后凡是算平均分、算比例、算钱的地方，都要记得「让算式里出现一个小数」，
常见写法是 `(double) sum / count`。

这个坑在后面反复出现，比如 `Temperature1.java` 里必须写 `5.0 / 9.0` 而不能写 `5 / 9`
（`5 / 9` 的结果是 0，整个换算公式就全废了）。

### 2.2 `nextLine` 和 `nextInt` 混用的坑 `MyInformation.java`

```java
int age = sc.nextInt();     // 只读走数字，「回车」还留在输入里
sc.nextLine();              // ← 这一句是专门用来把那个回车吃掉的
String motto = sc.nextLine();  // 不写上面那句，这句会读到空行
```

`nextInt()` 读完数字就停了，**不会把后面那个回车符也带走**。
紧接着的 `nextLine()` 一看「咦有个回车」，立刻读完返回一个空字符串 ——
表现出来就是「程序好像自己跳过了这一步，没让我输入」。

### 2.3 从「写代码」到「写方法」：`LeapYear2.java`

先看 `LeapYear.java`：闰年判断直接写在 `main` 里面，只能判断一年。
再看 `LeapYear2.java`：判断逻辑被抽成了一个独立方法

```java
static boolean isLeapYear(int year) {
    if (year % 4 == 0 && year % 100 != 0 || year % 400 == 0) {
        return true;
    } else {
        return false;
    }
}
```

然后 `main` 里只要一行 `isLeapYear(years[i])` 就能反复用。
**这就是「方法」最大的好处：写一次，到处用。**

### 2.4 循环嵌套的经典题：`Table99.java`

```java
for (int i = 1; i <= 9; i++) {          // 外层：第几行
    for (int j = 1; j <= i; j = j + 1) { // 内层：这一行打印几列
        System.out.print(j + "*" + i + "=" + j * i + "\t");
    }
    System.out.println();               // 一行打完了，换行
}
```

**三层理解方式：**

1. 外层 `i` 是「第几行」，从 1 到 9；
2. 内层 `j` 是「这一行里的第几列」，结束条件是 `j <= i` ——
   第 1 行只打 1 列，第 2 行打 2 列，所以整体是个三角形；
3. `print` 不换行（把算式连起来），`println` 换行（结束这一行），
   `"\t"` 是制表符（让每列对齐）。

**动手改一改：** 把内层条件 `j <= i` 改成 `j <= 9`，看看打印出来是什么形状。

## lesson01 · 猜数字游戏 `GuessNumber.java`

**在练什么：** 把前面零散的知识点拼成一个完整的小程序（这是第一个「像样的程序」）。

**运行后你会看到：**

```
我想好了一个 1 到 50 的数字
你有 5 次机会
请输入你的猜测：25
太大了喵~
还剩 4 次机会。
请输入你的猜测：13
太小了喵~
还剩 3 次机会。
请输入你的猜测：18
恭喜！你用了 3 次猜中了。
```

**代码里最值得注意的地方：**

| 这行代码 | 为什么重要 |
| --- | --- |
| `random.nextInt(50) + 1` | `nextInt(50)` 只会给 0~49，所以**必须加 1** 才能变成 1~50。这是最容易踩的坑 |
| `attempts++` 放在输入校验**之后** | 输入非整数、输入越界、输入 0 退出，这几种情况都**不算用掉一次机会**。顺序放错，次数就会算错 |
| `continue` | 「跳过本次循环剩下的部分，直接开始下一轮」。用它做输入校验很方便 |
| `guessedCorrectly` 标记位 | 为什么要多一个 boolean？因为循环可能在「猜中」时结束，也可能在「次数用完」时结束。循环结束后单看 `attempts` **分不清是哪种情况**，所以要单独记一笔 |
| `scanner.hasNextInt()` | 先「看一眼」下一个输入是不是整数。如果不是就 `scanner.next()` 把它丢掉，否则它会一直卡在那里导致死循环 |

**动手改一改：**

- 把 `maxAttempts` 改成 10，看看提示文字和机会次数是不是跟着变了；
- 把范围从 1~50 改成 1~100（记得 `nextInt` 里的数字和输入校验的条件**都要改**）；
- 想办法让程序在猜中后告诉玩家「你用了3次，平均每猜2个数字就能中一次」——想想该怎么算。

## lesson03 · 判断大小 `GuessCompare.java`

**在练什么：** `if - else if - else` 三分支判断。

**运行后你会看到：**

```
请输入一个整数
20
太小了喵
```

**代码里最值得注意的地方：**

- 三个分支的判断顺序：**先判断 `<`，再判断 `>`，剩下的必然是「相等」**，于是用 `else` 兜底即可，不用再写一次 `==`；
- `else if` 和两个连续的 `if` 是**不一样的**：`else if` 前面命中了后面就不看了，写成两个独立 `if` 在逻辑上可能两个都执行。

**动手改一改：**

- 把 `secret` 改成 100，试试各种输入；
- 把三个分支的判断条件故意写反（`guess > secret` 输出了「太小了」），体会一下逻辑写反是什么效果。

## lesson04 · 循环猜 3 次 `GuessThreeTimes.java`

**在练什么：** 把 lesson03 的判断**套进 while 循环**，并加入次数控制。

**运行后你会看到：**

```
我想好了一个数字
你有3次机会
请输入你的猜测
10
太小了
请输入你的猜测
30
太大了
请输入你的猜测
25
恭喜，你猜中了
```

**代码里最值得注意的地方：**

| 这行代码 | 为什么重要 |
| --- | --- |
| `while (attempts < maxAttempts)` | 循环条件就是「机会还没用完」。想清楚这个条件，循环就不难写 |
| `break` | 猜中之后没必要再循环了，直接跳出。**循环结束时 `attempts` 可能是 3，也可能是猜中的那一次**，这就是后面要判断的原因 |
| `if (!guessedCorrectly && attempts == maxAttempts)` | `!` 表示「取反」。两个条件用 `&&` 连起来：既没猜中、次数又用完了，才公布答案。只写一个条件会出错 |

**动手改一改：**

- 把 `maxAttempts` 改成 5，和 lesson01 对比一下两课代码的差别；
- **故意做一个错误实验**：把最后那个 `if` 改成只写 `attempts == maxAttempts`（去掉 `!guessedCorrectly`），然后在**第 3 次刚好猜中**，看看程序会不会多说一句「机会用完了，答案是25」——这就是那个标记位存在的意义。

## lesson05 · 方法练习 `DigitMethods.java`

**在练什么：** 定义方法、调用方法、`return` 返回值。把「一件事」装进一个方法里。

**运行后你会看到：**

```

```

**代码里最值得注意的地方：**

| 方法 | 用到的技巧 |
| --- | --- |
| `getOnesPlace(456)` → 6 | `number % 10`：对 10 取余数，剩下的就是个位 |
| `getTensPlace(456)` → 5 | `number / 10 % 10`：先用整数除法去掉个位得到 45，再取余得到 5 |
| `getHundredsPlace(456)` → 4 | `number / 100 % 10`：先去掉后两位得到 4，再取余还是 4 |
| `readThreeDigitNumber(sc)` | 一个**永不返回非法值**的方法：用 `while (true)` 包住，只有合法时才 `return` |

**关于「方法」最容易搞混的一点：**

- `return number;` —— 这个方法**有返回值**，调用它的地方能拿到结果：`int ones = getOnesPlace(number);`
- `System.out.println(...)` —— 只是把字打在屏幕上，**不算返回**。写 `int ones = System.out.println(...)` 是编译不过的；
- 方法的**返回类型**（签名里的 `int`）和实际 `return` 出去的东西必须对得上。

### 3.1 数组到底是什么 `ArrayDemo1.java` / `ArrayDemo2.java`

**运行 `ArrayDemo1` 你会看到：**

```
[I@2f92e0f4
```

（`@` 后面的数字每次运行都不一样，这很正常。）

**为什么不是 `12 13 14 15`？**

因为数组变量里存的**不是元素本身，而是「这片数据在内存里的地址」**。
`[I` 的意思是「一维 int 数组」，`@` 后面是十六进制地址。
想看到元素，必须用「索引」把元素取出来。

**运行 `ArrayDemo2` 你会看到：**

```
1
1
100
```

前两个 `1` 是「0 索引上的元素」，最后变成 `100` 是因为执行了 `arr[0] = 100;` —— **赋值会覆盖原来的数据**。

> **初学者最容易忘的一条：索引从 0 开始。**
> 数组有 5 个元素，它们的索引是 `0 1 2 3 4`，**最后一个的索引是 4，不是 5**。
> 写成 `arr[5]` 会报 `ArrayIndexOutOfBoundsException`（数组下标越界）。

### 3.2 遍历的三种写法 `ArrayDemo3.java`

**运行你会看到 `1 2 3 4 5` 打印了两遍**（第一遍是手动写的，第二遍是循环写的）。

```java
// 方案一：手动逐个打印——5 个元素还行，100 个就惨了
System.out.println(arr[0]);
System.out.println(arr[1]);
...

// 方案二：写死循环次数——数组长度一变就得改代码
for (int i = 0; i < 5; i++) { ... }

// 方案三（推荐）：用 length 动态拿到长度
for (int i = 0; i < arr.length; i++) { ... }
```

**把 for 循环拆开看，就没那么神秘了：**

```java
for (int i = 0; i < arr.length; i++)
//   ①起始  ②结束条件   ③每轮结束后的动作
```

① `int i = 0`：从第 0 个索引开始；
② `i < arr.length`：只要索引还没超出范围就继续（长度 5 → i 最大取 4，正好是最后一项）；
③ `i++`：每轮结束索引加 1；
循环体 `arr[i]`：第 i 轮拿到的就是第 i 个元素。

**记住这条：`i < arr.length` 里的 `<` 不能写成 `<=`**，否则最后一轮 `i = 5`，取 `arr[5]` 直接越界报错。

### 3.3 数组的三个经典练习

**`ArrayTest1` 求和**（输出：`总和是：15`）

```java
int sum = 0;                                  // 累加器要从 0 开始
for (int i = 0; i < arr.length; i++) {
    sum = sum + arr[i];                       // 每轮把当前元素加进去
}
```

**`ArrayTest2` 统计个数**（输出：`3`、`6`、`9`、`数组中能被3整除的数字有3个`）

```java
int count = 0;                                // 计数器从 0 开始
for (int i = 0; i < arr.length; i++) {
    if (arr[i] % 3 == 0) {                    // % 3 == 0 就是「能被 3 整除」
        count++;
    }
}
```

**`ArrayTest3` 按规则换算**（输出：`2 1 6 2 10 3 14 4 18 5`）

```java
if (arr[i] % 2 != 0) {                        // 奇数
    result = arr[i] * 2;
} else {                                      // 偶数
    result = arr[i] / 2;
}
```

> 注意：这里只是把**算出来的结果打印出去**，数组本身**没有被修改**。
> 如果想让数组真的被改掉，要写 `arr[i] = arr[i] * 2;`。

**`ArrayPractice2` 求最大值**（输出：`5`）

```java
int max = arr[0];                             // 先假设第 0 个元素最大
for (int i = 0; i < arr.length; i++) {
    if (arr[i] > max) {                       // 发现有更大的
        max = arr[i];                         // 就把它记成新的最大值
    }
}
```

> 这个「先假设第一个最大、再逐个挑战」的思路，就是 lesson07 要自己动手写的题目。

### 3.4 综合练习 `ArrayPractice.java`

**运行后你会看到（输入 `90 85 78 92 88`）：**

```
请输入第1个成绩：
90
...
输入的成绩为：
第1个成绩：90
...
总分是：433
平均分是：86.6
```

**全课最重要的一个坑在这里：**

```java
double average = (double) sum / scores.length;
```

如果不加 `(double)`，写成了 `sum / scores.length`，结果会是 `86.0` 而不是 `86.6` ——
因为**两个整数相除，Java 会做「整数除法」，直接把小数部分扔掉**（433 / 5 = 86，不是 86.6）。
加上 `(double)` 相当于把 sum 临时变成小数，除法就正常了。

**动手改一改：**

- 把 `(double)` 删掉运行一次，亲眼看看差别（这是感受最深的一种学法）；
- 在平均分下面再加一行，输出最高分（把 `ArrayPractice2` 的 `max` 逻辑搬过来）；
- 把数组长度从 5 改成 3，其他代码都不用动——体会一下用 `arr.length` 而不是写死 5 的好处。

## 附：怎么把这些注释变成网页版 API 文档

代码里每个类、每个方法上面都写了 `/** ... */` 注释（这叫 Javadoc 注释）。
JDK 自带一个命令，可以把这些注释**自动变成一个网页版说明书**：

```bash
# 在项目根目录（能看到 src 的那一层）执行
javadoc -encoding UTF-8 -charset UTF-8 -d docs/api \
  -sourcepath src \
  -subpackages lesson01:lesson02:lesson03:lesson04:lesson05:lesson06:lesson07:utils
```

执行完成后，用浏览器打开 `docs/api/index.html`，就能看到按类和方法整理好的
「参数是什么、返回什么」的网页文档了。

> 生成出来的 `docs/api/` 属于「产物」，已经写进 `.gitignore`，不会上传到 GitHub。
> 想更新文档，重新跑一遍上面的命令即可。
