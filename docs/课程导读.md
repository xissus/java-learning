### for 循环的三个部分

```java
for (int i = 10; i >= 1; i = i - 2)
//   ①起始值   ②结束条件   ③每轮结束后怎么变
```

`Loop.java` 里是 `i = i - 2`，每次减 2，所以只会经过 10、8、6、4、2，一共 5 次；`Sum100.java` 里是 `i = i + 1`，从 1 走到 100。这三部分想清楚了，循环基本就不会写错。

### Sum200 里保留的那个坑

```java
for (int i = 1; i <= 50; i++) {
    a = a + i;
    System.out.println("总和为" + a);   // ← 打印写在了循环「里面」
}
```

`println` 写在循环里面，就会每加一次打印一行，出来 50 行；写在外面（也就是 `}` 之后），才会只打印最后那个结果。这个「打印语句放错层级」的坑我踩过，所以留在文件里当提醒。

**动手改一改：** 把 `Sum200.java` 里的 `System.out.println` 挪到循环外面，看输出从 50 行变成几行。

下面四个是这一批里最值得单独说的。

### 2.1 整数除法 `Divide.java`

```java
System.out.println(10 / 3);   // 输出 3     ← 不是 3.3333
System.out.println(10.0 / 3); // 输出 3.3333333333333335
```

两个整数相除，Java 会直接丢掉小数部分。这个坑后面会反复撞上：凡是算平均分、算比例、算钱的地方，都得保证算式里出现一个小数，常见写法是 `(double) sum / count`。

`Temperature1.java` 里就必须写 `5.0 / 9.0`。写成 `5 / 9` 的话结果是 0，整个换算公式就废了。

### 2.2 `nextLine` 和 `nextInt` 混用的坑 `MyInformation.java`

```java
int age = sc.nextInt();        // 只读走数字，「回车」还留在输入里
sc.nextLine();                 // ← 这一句专门用来把那个回车吃掉
String motto = sc.nextLine();  // 不写上面那句，这句会读到空行
```

`nextInt()` 读完数字就停了，不会把后面那个回车符也带走。紧接着的 `nextLine()` 一看「咦有个回车」，立刻读完返回一个空字符串 —— 表现出来就是「程序好像自己跳过了这一步，没让我输入」。

### 2.3 从「写代码」到「写方法」`LeapYear2.java`

`LeapYear.java` 里闰年判断直接写在 `main` 中，只能判断一年。`LeapYear2.java` 把判断逻辑抽成了独立方法：

```java
static boolean isLeapYear(int year) {
    if (year % 4 == 0 && year % 100 != 0 || year % 400 == 0) {
        return true;
    } else {
        return false;
    }
}
```

`main` 里只要写一行 `isLeapYear(years[i])` 就能反复用。写一次、到处用，这是方法最大的好处。

### 2.4 循环嵌套 `Table99.java`

```java
for (int i = 1; i <= 9; i++) {           // 外层：第几行
    for (int j = 1; j <= i; j = j + 1) { // 内层：这一行打印几列
        System.out.print(j + "*" + i + "=" + j * i + "\t");
    }
    System.out.println();                // 一行打完了，换行
}
```

外层 `i` 是第几行，从 1 到 9。内层 `j` 是这一行里的第几列，结束条件是 `j <= i` —— 第 1 行只打 1 列，第 2 行打 2 列，所以整体是个三角形。`print` 不换行（把算式连起来），`println` 换行（结束这一行），`"\t"` 是制表符（让每列对齐）。

**动手改一改：** 把内层条件 `j <= i` 改成 `j <= 9`，看打印出来是什么形状。

### 3.1 什么时候用 `if - else if`，什么时候用 `switch`

这是课上专门记下来的一条。

要对**范围**做判断，比如「95~100 分」「90~94 分」，用 `if ... else if ... else if`；只是从**几个固定选项**里挑一个，比如「1 号查机票、2 号订机票」，用 `switch`。

`Score.java` 是前者的典型，`UserChoose.java` 和 `WeekSwitch.java` 是后者的典型。

### 3.2 `switch` 的两条规矩：`break` 和 `default`

```java
switch (choose) {
case 1:
    System.out.println("机票查询");
    break;                 // ① 每个 case 后面都要有它
case 2:
    System.out.println("机票预订");
    break;
default:                   // ② 所有 case 都没命中时，走这里
    System.out.println("退出服务");
    break;
}
```

**`break` 不能忘。** 命中一个 `case` 之后程序不会自动停下来，而是顺着往下继续执行，一直到碰上 `break` 或者整个 `switch` 走完。这种「一路往下滑」的现象叫 `case` 穿透。

**`default` 是兜底。** 用户输入 9、输入 -1 这种没列出来的值，如果没有 `default`，程序就什么都不打印，人坐在那儿一脸茫然。写上 `default`，等于告诉程序「遇到不认识的我该说什么」。

### 3.3 `case` 穿透不一定是坏事

课上还提到「利用 `case` 穿透简化程序」，例子是判断哪天是工作日、哪天是休息日。因为穿透会顺着往下滑，所以可以让好几个 `case` 共用同一段代码：

```java
switch (week) {
case 1:
case 2:
case 3:
case 4:
case 5:
    System.out.println("工作日");   // 1~5 都会滑到这里
    break;                          // ← 这个 break 是共用的，只有一个
case 6:
case 7:
    System.out.println("休息日");
    break;
default:
    System.out.println("没有这个星期");
}
```

前 5 个 `case` 什么代码都不写、直接连着写，程序就会一路穿到 `"工作日"` 那一句。这比写五遍 `System.out.println("工作日")` 省事得多。所以穿透是工具，不是错误 —— 关键看是不是故意这么写的。

### 3.4 JDK 12 之后可以用 `->` 简化 `break`

这是课上记下来的一条，照着手稿抄在这里。

老写法每个分支都要配一个 `break`，新写法直接用 `->`，不用再写 `break`：

```java
int number = 1;
switch (number) {
case 1 -> {
    System.out.println("一");
}
case 2 -> System.out.println("二");
default -> System.out.println("其它");
}
```

区别就两处：一个分支，老写法是 `case 1:` 加代码加 `break;`，新写法是 `case 1 ->` 加代码，没有 `break`；分支里不止一行的时候，新写法要用 `{ }` 把几行包起来。

现在不用写这种新写法。仓库里这几份代码用的都是传统的 `case ... break`，学校考试和教材也是从传统写法讲起的。这里记下来只是留个印象，以后在别人的代码里见到 `case 1 ->`，知道那是怎么回事就行。

### 3.5 这几份代码里可以自己动手改的地方

下面这些都不是「错」，是留给自己的口子。

**1. `Score.java` 输入 `94.5` 会得到「挨揍」。**

分段写的是 `>= 95`、`>= 90 && <= 94`、`>= 80 && <= 89`，所以 94 和 95 之间有一条缝，94.5 谁都不接，掉进了 `else`。改法有两种：把中间段写成 `Score > 94`，或者干脆只判下界（`>= 95` / `>= 90` / `>= 80`）—— `else if` 是从上往下挨个试的，只判下界就够。

**2. `UserChoose.java` 的 `default` 打印的也是「退出服务」，和 `case 4` 一模一样。**

想一想：用户输了个 9，屏幕上冒出「退出服务」，合适吗？

**3. `test2.java` 用的是三个并列的 `if`。**

并列的 `if` 各判断各的，万一两个布尔变量同时是 `true`，就会打印两行。红绿灯明明是互斥的（只能是其中一种），改成 `if - else if - else` 更贴合现实。

**4. `FilmSeat.java` 的票号 0 走的是哪一边？**

提示：代码里判断的是 `ticket % 2 == 1`，0 除 2 余 0。跑一下看符不符合直觉。

**5. `LinearEquation.java` 有两处值得动手。**

一是提示语里的错别字，写的是「**次**方程组无解」，应该是「**此**方程组无解」。程序输出也是给人看的，顺手改掉。

二是更值得想的一点：行列式为 0 的时候，真的只有「无解」一种可能吗？代码里 `a·d − b·c == 0` 就直接打印无解。拿这两组数试试：

| a | b | e | c | d | f | 情况 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 2 | 2 | 2 | 第二个方程是第一个方程乘 2 |
| 1 | 1 | 1 | 2 | 2 | 3 | 第二个方程是第一个方程乘 2 再加 1 |

第一组两个方程其实是同一个，满足它的 x、y 有无穷多组；第二组两个方程互相矛盾，一组解都没有。数学上前者叫「有无穷多组解」，后者才是「无解」，但程序把两种情况都印成了无解。

要改的话，思路是：判断完 `a·d − b·c == 0` 之后，再看常数项配不配得上，配得上就是无穷多解，配不上才是无解。这题不着急做，等学完方法、能把判断抽成一个独立函数时会顺手很多。

**6. `WeekSwitch.java` 里 `case 1` 那一段缩进比别的浅一层**（`System.out` 顶到了行首）。选中整个文件按 `Ctrl + Shift + F`，Eclipse 会自动排整齐。

**7. 两个命名建议。** 类名 `test2` 按 Java 规范要写成大写开头（`Test2`）；变量 `Money`、`Score` 开头应该小写（`money`、`score`）。不影响运行，但养成习惯以后看别人的代码会顺很多。

## lesson01 · 猜数字游戏 `GuessNumber.java`

前面零散学的知识点，在这里第一次拼成一个完整的小程序。程序随机想一个 1 到 50 的数，最多 5 次机会猜中它；输入 0 可以退出，输入非整数或超出范围不算用掉机会。

跑起来大概是这样：

```
我想好了一个 1 到 50 的数字
你有 5 次机会
请输入你的猜测：25
太大了喵~
还剩 4 次机会。
请输入你的猜测：13
太小了喵~
还剩 3 次机会。
请输入你的猜测：18
恭喜！你用了 3 次猜中了。
```

几处关键的地方：

`random.nextInt(50) + 1` —— `nextInt(50)` 只会给 0~49，必须加 1 才能变成 1~50。这是最容易踩的坑。

`attempts++` 放在输入校验**之后** —— 输入非整数、输入越界、输入 0 退出，这几种情况都不算用掉一次机会。顺序放错，次数就会算错。

`continue` 的意思是「跳过本次循环剩下的部分，直接开始下一轮」，拿它做输入校验很方便。

`guessedCorrectly` 这个标记位 —— 为什么要多一个 boolean？因为循环可能在猜中时结束，也可能在次数用完时结束，循环结束后单看 `attempts` 分不清是哪种情况，所以要单独记一笔。

`scanner.hasNextInt()` 是先「看一眼」下一个输入是不是整数。如果不是就 `scanner.next()` 把它丢掉，否则它会一直卡在那里导致死循环。

**动手改一改：** 把 `maxAttempts` 改成 10，看提示文字和机会次数是不是跟着变了；把范围从 1~50 改成 1~100（记得 `nextInt` 里的数字和输入校验的条件都要改）；或者想办法让程序在猜中后告诉玩家「你用了 3 次，平均每猜 2 个数字就能中一次」，想想该怎么算。

## lesson03 · 判断大小 `GuessCompare.java`

`if - else if - else` 三分支，判断猜的数和答案谁大谁小。

三个分支的判断顺序值得注意：先判断 `<`，再判断 `>`，剩下的必然是相等，于是用 `else` 兜底就行，不用再写一次 `==`。

另外 `else if` 和两个连续的 `if` 是不一样的。`else if` 前面命中了后面就不看了；写成两个独立 `if`，逻辑上可能两个都执行。

**动手改一改：** 把 `secret` 改成 100 试试各种输入；或者把三个分支的判断条件故意写反（猜大了却输出「太小了」），体会一下逻辑写反是什么效果。

## lesson04 · 循环猜三次 `GuessThreeTimes.java`

把 lesson03 的判断套进 `while` 循环，再加上次数控制。

```
我想好了一个数字
你有3次机会
请输入你的猜测
10
太小了
...
```

`while (attempts < maxAttempts)` 的循环条件就是「机会还没用完」。这个条件想清楚了，循环就不难写。

猜中之后用 `break` 跳出，没必要再循环。要注意**循环结束时 `attempts` 可能是 3，也可能是猜中的那一次**，这就是后面还要判断的原因。

最后那个 `if (!guessedCorrectly && attempts == maxAttempts)` 里，`!` 表示取反，两个条件用 `&&` 连起来：既没猜中、次数又用完了，才公布答案。只写一个条件会出错。

**动手改一改：** 把 `maxAttempts` 改成 5，和 lesson01 对比两课代码的差别。或者故意做个错误实验：把最后那个 `if` 改成只写 `attempts == maxAttempts`（去掉 `!guessedCorrectly`），然后在第 3 次刚好猜中，看程序会不会多说一句「机会用完了，答案是 25」—— 这就是那个标记位存在的意义。

## lesson05 · 方法练习 `DigitMethods.java`

定义方法、调用方法、`return` 返回值。把「一件事」装进一个方法里。

```
请输入一个100到999之间的三位整数：
456
个位是：6
十位是：5
百位是：4
1到50的总和是：1275
```

取各位数字的办法是同一套：`number % 10` 拿到个位；`number / 10 % 10` 先用整数除法去掉个位，再取余拿到十位；`number / 100 % 10` 同理拿到百位。

`readThreeDigitNumber(sc)` 是个值得看的写法：用 `while (true)` 把输入包起来，只有合法时才 `return`，所以这个方法永远不会返回非法值。

关于「方法」最容易搞混的一点：`return number;` 是这个方法**有返回值**，调用它的地方能拿到结果，比如 `int ones = getOnesPlace(number);`。而 `System.out.println(...)` 只是把字打在屏幕上，**不算返回** —— 写成 `int ones = System.out.println(...)` 是编译不过的。另外方法的返回类型（签名里的 `int`）和实际 `return` 出去的东西必须对得上。

**动手改一改：** 再写一个 `getThousandsPlace(int number)` 取千位（提示：`number / 1000 % 10`）；把 `sumTo(50)` 改成 `sumTo(100)`，先猜结果变成多少（1+2+…+100 = 5050）；或者新增一个 `isEven(int number)`，返回 `boolean`，判断是不是偶数，然后在 `main` 里调用它。

## lesson06 · 数组专题

这一课文件最多，建议按这个顺序看。

1. `ArrayDemo1.java` —— 数组里存的是什么？为什么打印出来是 `[I@2f92e0f4`
2. `ArrayDemo2.java` —— 怎么用索引取值、改值
3. `ArrayDemo3.java` —— 怎么把 5 行打印变成 1 行循环
4. `ArrayPractice2.java` —— 遍历加比较，求最大值
5. `ArrayTest1.java` —— 遍历加累加，求和
6. `ArrayTest2.java` —— 遍历加判断，统计个数
7. `ArrayTest3.java` —— 遍历加分支，按规则换算
8. `ArrayPractice.java` —— 综合：录入数据、统计、输出
9. `ArrayTest4.java` —— 数组不只装数字，也能装字符串

### 6.1 数组到底是什么 `ArrayDemo1.java` / `ArrayDemo2.java`

跑 `ArrayDemo1` 只会看到这么一行：

```
[I@2f92e0f4
```

（`@` 后面的数字每次运行都不一样，这很正常。）

为什么不是 `12 13 14 15`？因为数组变量里存的**不是元素本身，而是这片数据在内存里的地址**。`[I` 的意思是「一维 int 数组」，`@` 后面是十六进制地址。想看到元素，必须用索引把元素取出来。

跑 `ArrayDemo2` 会看到 `1`、`1`、`100`。前两个 `1` 是 0 索引上的元素，最后变成 `100` 是因为执行了 `arr[0] = 100;` —— 赋值会覆盖原来的数据。

有一条初学者最容易忘：**索引从 0 开始**。数组有 5 个元素，索引是 `0 1 2 3 4`，最后一个的索引是 4 不是 5。写成 `arr[5]` 会报 `ArrayIndexOutOfBoundsException`。

### 6.2 遍历的三种写法 `ArrayDemo3.java`

跑起来会看到 `1 2 3 4 5` 打印两遍（第一遍手动写的，第二遍循环写的）。

```java
// 方案一：手动逐个打印 —— 5 个元素还行，100 个就惨了
System.out.println(arr[0]);
System.out.println(arr[1]);
...

// 方案二：写死循环次数 —— 数组长度一变就得改代码
for (int i = 0; i < 5; i++) { ... }

// 方案三（推荐）：用 length 动态拿到长度
for (int i = 0; i < arr.length; i++) { ... }
```

把 for 拆开看就没那么神秘了：

```java
for (int i = 0; i < arr.length; i++)
//   ①起始  ②结束条件   ③每轮结束后的动作
```

`int i = 0` 是从第 0 个索引开始；`i < arr.length` 是只要索引还没超出范围就继续（长度 5 的话 i 最大取 4，正好是最后一项）；`i++` 是每轮结束索引加 1。循环体里的 `arr[i]`，第 i 轮拿到的就是第 i 个元素。

注意 `i < arr.length` 里的 `<` 不能写成 `<=`，否则最后一轮 `i = 5`，取 `arr[5]` 直接越界报错。

### 6.3 数组的三个经典练习

`ArrayTest1` 求和（输出 `总和是：15`）：

```java
int sum = 0;                                  // 累加器要从 0 开始
for (int i = 0; i < arr.length; i++) {
    sum = sum + arr[i];                       // 每轮把当前元素加进去
}
```

`ArrayTest2` 统计个数（输出 `数组中能被3整除的数字有3个`）：

```java
int count = 0;                                // 计数器从 0 开始
for (int i = 0; i < arr.length; i++) {
    if (arr[i] % 3 == 0) {                    // % 3 == 0 就是能被 3 整除
        count++;
    }
}
```

`ArrayTest3` 按规则换算（输出 `2 1 6 2 10 3 14 4 18 5`）：

```java
if (arr[i] % 2 != 0) {                        // 奇数
    result = arr[i] * 2;
} else {                                      // 偶数
    result = arr[i] / 2;
}
```

这里只是把算出来的结果打印出去，数组本身没有被改。想让数组真的被改掉，得写 `arr[i] = arr[i] * 2;`。

`ArrayPractice2` 求最大值（输出 `5`）：

```java
int max = arr[0];                             // 先假设第 0 个元素最大
for (int i = 0; i < arr.length; i++) {
    if (arr[i] > max) {                       // 发现有更大的
        max = arr[i];                         // 就把它记成新的最大值
    }
}
```

这个「先假设第一个最大、再逐个挑战」的思路，就是 lesson07 的 `ArrTest5.java` 要正式练的题。

### 6.4 综合练习 `ArrayPractice.java`

输入 `90 85 78 92 88`，会看到总分 433、平均分 86.6。

这一课最重要的坑在这儿：

```java
double average = (double) sum / scores.length;
```

不加 `(double)`、写成 `sum / scores.length`，结果会是 `86.0` 而不是 `86.6`。因为两个整数相除，Java 会做整数除法，直接把小数部分扔掉（433 / 5 = 86）。加上 `(double)` 相当于把 sum 临时变成小数，除法就正常了。

**动手改一改：** 把 `(double)` 删掉运行一次，亲眼看看差别，这是感受最深的一种学法；在平均分下面再加一行输出最高分（把 `ArrayPractice2` 的逻辑搬过来）；或者把数组长度从 5 改成 3，其他代码都不用动 —— 体会一下用 `arr.length` 而不是写死 5 的好处。

### 6.5 数组也能装文字 `ArrayTest4.java`

`String[] arr = new String[50];` —— 把 `int[]` 换成 `String[]`，其他写法完全一样。

这个文件不太适合直接跑，它会连着问你要 50 个姓名，一个个输完很累。想看效果，把两处 `arr.length` 都临时改成 3，输 3 个名字试试就行（试完记得改回来，或者直接不保存关掉）。

另外注意 `scanner.next()` 读到空格就停，所以姓名里的空格会被当成下一个输入。

## lesson07 · 数组综合题 `ArrTest5.java` / `ArrTest6.java`

这是课堂上跟着老师敲的两道数组综合题。

### 7.1 求数组最大值 `ArrTest5.java`

思路是先认定第 0 个元素最大（`max = arr[0]`），再拿后面每个元素跟 `max` 比，谁大就把谁记下来。循环结束后 `max` 就是最大值。

```java
int[] arr = { 33, 5, 22, 44, 55 };
int max = arr[0];                       // 先假设第 0 个最大
for (int i = 0; i < arr.length; i++) {
    if (arr[i] > max) {
        max = arr[i];                   // 遇到更大的就换掉
    }
}
System.out.println(max);                // 输出 55
```

有个值得想的问题：为什么 `max` 的初值要写成 `arr[0]`，不能图省事写成 `max = 0`？

因为数组里可能有负数。如果数组是 `{-5, -8, -2}`，`0` 比它们全都大，程序会错误地输出 `0`。初值必须是数组里真实存在的元素，比较才有意义。

**动手改一改：** 把程序改成求最小值，只需要改比较的方向（`<`）和打印的文字。

### 7.2 随机数综合练习 `ArrTest6.java`

题目是斯坦福大学原题，第 3 问难度较高：

1. 生成 10 个 1~100 之间的随机数存入数组
2. 求所有随机数的和
3. 求所有数据的平均数
4. 统计有多少个数据比平均数小

关键代码：

```java
int[] arr = new int[10];                // 动态初始化
Random r = new Random();
for (int i = 0; i < arr.length; i++) {
    int number = r.nextInt(100) + 1;    // nextInt(100) 得到 0~99，+1 才是 1~100
    arr[i] = number;
}
```

跑起来会看到类似这样的输出（因为每次生成的随机数不同，你的结果不会完全一样）：

```
随机数的总和为550
数组的平均数为55.0
一共有5个数据比平均数小
52 88 31 67 44 79 15 93 26 55
```

这个文件里保留了一处踩坑记录：

```java
double avg = sum / arr.length;          // 这里其实不精确
```

`sum` 和 `arr.length` 都是整数，整数相除会直接砍掉小数部分。比如总和是 547，`547 / 10` 会得到 54，不是 54.7。正确的写法是先转成小数再除：

```java
double avg = (double) sum / arr.length; // 加上 (double) 才会保留小数
```

这就是 day01、day02 反复撞上的「整数除法截断」。这一行保留原样当纪念，文件注释里也写了说明，以后回看时就知道自己在这里踩过坑。

## other · 自己练手的小程序

这个包里是课程之外自己给自己出的题，一共 6 个文件。前四个分别练求根公式、强制类型转换、标志变量、循环累乘；后两个是同一道题的两种解法（数组版和不用数组版），摆在一起看能想清楚数组到底解决了什么问题。

### 1. 解一元二次方程 `QuadraticFormula.java`

用求根公式解 `ax² + bx + c = 0`。这题不在课程里，是自己找来的，把学过的东西串起来用一遍。

求根公式是 `x = (-b ± √(b²-4ac)) / 2a`，其中 `b² - 4ac` 叫判别式（代码里的 `delta`），它的正负决定根的情况：

| 判别式 | 根的情况 |
| --- | --- |
| `delta > 0` | 两个不相等的实根 |
| `delta == 0` | 两个相等的实根（其实只有一个） |
| `delta < 0` | 在实数范围内没有根 |

输入 `1`、`-3`、`2`，会看到「方程有两个不相等的实根」，`X1=2.0`、`X2=1.0`。验算一下：`x² - 3x + 2 = 0` 确实能分解成 `(x-1)(x-2) = 0`，两个根就是 1 和 2。

有一行要注意：

```java
double root = -b / (2.0 * a);      // 注意这里写的是 2.0，不是 2
```

为什么是 `2.0`？因为整数除法会砍掉小数。写 `2` 的话 `-b / (2 * a)` 就是整数运算，结果不精确。写成 `2.0` 才能得到小数。这个坑前面已经撞过两次了。

这里还学到一个新东西：`return`。

如果 `a` 输入 0，方程就不是二次方程了（退化成 `bx + c = 0`），再套求根公式就会除以 0，算出来是 `NaN`（不是一个数）和 `Infinity`（无穷大）。第一次跑这个程序确实会出这个问题，后来补上了检查：

```java
int a = sc.nextInt();

// a 不能为 0，否则就不是二次方程了
if (a == 0) {
    System.out.println("a 不能为 0，否则就不是一元二次方程了");
    sc.close();
    return;                  // 直接结束程序
}

// 走到这里说明 a 没问题，继续读 b 和 c
System.out.println("请输入方程的系数b：");
int b = sc.nextInt();
```

`return` 的作用是立刻结束当前方法，后面的代码一行都不执行；写在 `main` 里就是直接结束整个程序。它和 `break` 的区别是：`break` 只跳出循环，`return` 是直接走人，连方法都不待了。

输入 `0`、`2`、`3` 的话，程序只会打印一句「a 不能为 0，否则就不是一元二次方程了」，不会再问 b 和 c —— 因为 `return` 一执行，程序就结束了。

另一种写法可以自己想：现在是「输错了就退出」，更友好的是「输错了让你重新输」，用 `while` 循环包起来直到输对为止。`lesson01/GuessNumber` 里写过类似的循环，可以试着改改看。

### 2. 强制类型转换把小数变整数 `And.java`

`(int)` 强制类型转换，把一个带小数的结果砍成整数。题目是算 `45.98` 与 `78.12` 的和，要求输出整数。

这题没用 `Scanner`，两个数字直接写在代码里，因为题目给的就是固定的两个数。

```java
int sum = (int) (a + b);   // 先做加法，再把结果截成整数
```

这一行干了两件事，顺序不能反：括号里的 `a + b` 先算（括号优先级最高），得到 `124.1`；然后 `(int)` 把这个小数的小数部分砍掉，得到 `124`。

那对括号必须写。写成 `(int) a + b` 就变成「先把 a 转成 45，再加 78.12」，结果是 `123.12`，完全跑偏了。

它是直接砍掉，不是四舍五入。所以输出是 `124` 而不是 `125`；就算和是 `124.9`，结果也还是 `124`。

**动手改一改：** 把 `45.98` 改成 `124.9` 看看（还是 `124`）。如果确实想四舍五入，Java 里有个现成的工具叫 `Math.round(数值)`，属于以后才会用到的东西，先知道有这么个工具就行。

### 3. 布尔标志变量 `Exercise1.java`

`boolean` 标志变量 —— 先记一个状态，再拿这个状态去决定该干什么。题目是：输入一个整数，大于 0 就输出它的 60%，否则输出这个数本身。

思路长这样：

```java
boolean a = false;        // 先假设条件不成立
if (num > 0) {
    a = true;             // 条件成立了，把状态改成 true
    if (a) { ... }        // 再根据状态决定做什么
}
```

这种「先记状态、后面再判断」的写法在真实项目里很常见。写过的 `lesson01/GuessNumber` 里，那个记录「猜没猜中」的变量就是同一个思路。

关于 60% 的写法：`(double) (num * 0.6)`，这里乘 `0.6` 而不是写 `num * 60 / 100`。因为 `60 / 100` 是整数除法，会被砍成 0。想让结果带小数，就得让小数参与运算。

输入 100 得到 `结果60.0`，输入 0 得到 `结果为0`，输入 -5 得到 `结果为-5`。

这里踩过一个坑，后来自己改对了，值得记住。最初 `else` 被写在了 `if (num > 0)` 的大括号**里面**，结果输入 0 或负数时程序什么都不打印 —— 因为外面那个 `if (num > 0)` 一旦不成立，里面的 `else` 根本轮不到执行，整段就被跳过去了。

改法很简单：把 `else` 挪出来，和 `if (a)` 写成平级。这样两个 `if` 各管一件事，上面那个只负责记住这个数是不是正数，下面那个负责按记下的状态走两条路，`num <= 0` 的那条退路就有人管了。

记住一点：`else` 只会跟离它最近的那个 `if` 配对，位置一挪意思就全变了。顺带复习一下，`{}` 大括号圈的是「哪些行属于这个 if」，所以大括号画到哪儿，答案就在哪儿。

### 4. 用循环算阶乘 `Exercise2.java`

累乘，和累加是同一个套路，只是把 `+` 换成了 `*`。题目是输入 `n`，用循环算出 `n!`。

核心就三行：

```java
long product = 1;                      // 累乘器，初始值是 1
for (int i = 1; i <= n; i++) {
    product = product * i;             // 每转一圈就多乘进去一个数
}
```

最容易搞错的是初始值要写 `1` 而不是 `0`。累加时写 `sum = 0`，因为加上 0 不影响结果；但累乘如果写 `product = 0`，不管乘多少次结果都还是 0。加法从 0 开始，乘法从 1 开始。

为什么用 `long` 而不是 `int`？`int` 最大约 21 亿，而 `13! = 6227020800` 已经超了；换成 `long`（能装到 900 亿亿）就够算到 `20!`。这属于「先把类型选大一点，省得溢出」。

输入 5 得到 `该数的阶乘为120`。另外两个边界情况可以自己试试：输入 0 得到 `该数的阶乘为1`（规定 `0! = 1`，代码里循环一次都不执行，`product` 还是初始的 1）；输入 -5 得到 `负数没有阶乘`（负数走的是另一个分支）。

### 5. 数组版：能被 7 整除的平方和 `Exercise3.java`

把学过的数组和累加串起来用，顺便想清楚这道题到底需不需要数组。

题目是算 1~500 中所有能被 7 整除的数的平方和，也就是把 7、14、21……这些数各自平方再加到一起。

分两步走。先把 1~500 装进数组：

```java
int[] arr = new int[500];
for (int i = 0; i < arr.length; i++) {
    arr[i] = i + 1;          // 数组下标从 0 开始，所以存进去的是 i + 1
}
```

再遍历数组，挑出能被 7 整除的，把它的平方加进累加器：

```java
long sum = 0;
for (int i = 0; i < arr.length; i++) {
    if (arr[i] % 7 == 0) {          // % 7 等于 0，就说明能被 7 整除
        sum = sum + arr[i] * arr[i];
    }
}
```

输出是 `结果为5969964`。这个数可以自己验算：1~500 里能被 7 整除的数是 7、14、……、497，一共 71 个，到 497 就停了，下一个 504 已经超过 500。

这一版最值得注意的是：数组在这儿一点计算的忙都没帮上，它只是把 1~500 先存起来，真正干活的还是第二遍循环。那既然这样为什么还要先存？这就引出下一版。

### 6. for 循环版：同一道题不用数组 `Exercise4.java`

同一道题换个写法，顺便想清楚数组到底解决什么问题。

```java
long sum = 0;
for (int i = 1; i <= 500; i++) {
    if (i % 7 == 0) {
        sum = sum + i * i;
    }
}
```

输出还是 `结果为5969964`，和 `Exercise3` 一模一样。

和数组版的区别只有一处：这里的 `i` 本身就是那个数，看一眼算完就可以扔，没必要先存起来。`Exercise3` 里那个「装数组」的循环，在这版里直接省掉了。

那什么时候非用数组不可？当你需要回头再碰一次这些数据的时候。比如要先把 10 个成绩全读完、再求平均分、再回头统计比平均分低的有几个 —— 这时候成绩必须留在数组里，因为平均分要读完了才知道，算出来之后还要拿每一个成绩去跟它比（lesson06 的 `ArrayPractice` 就是这么干的）。反过来，像这道题一样转一圈就算完的，不用数组反而更短。

数组不是必须的，它解决的是「数据要留下来、以后还要再用一次」的问题。把 `Exercise3` 和 `Exercise4` 摆在一起看，比单独看任何一个都更容易想通这一点。

## 附：怎么把这些注释变成网页版 API 文档

代码里每个类、每个方法上面都写了 `/** ... */` 注释，这叫 Javadoc 注释。JDK 自带一个命令，可以把这些注释自动变成一个网页版说明书：

```bash
# 在项目根目录（能看到 src 的那一层）执行
javadoc -encoding UTF-8 -charset UTF-8 -d docs/api \
  -sourcepath src \
  -subpackages day01:day02:day03:lesson01:lesson02:lesson03:lesson04:lesson05:lesson06:lesson07:other:utils
```

执行完用浏览器打开 `docs/api/index.html`，就能看到按类和方法整理好的「参数是什么、返回什么」的网页文档。

生成出来的 `docs/api/` 属于产物，已经写进 `.gitignore`，不会上传到 GitHub。想更新文档，重新跑一遍上面的命令即可。
